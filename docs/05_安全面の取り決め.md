# 05 安全面の取り決め

関与先の利用者識別番号と暗証番号を扱います。事故が起きると事務所の信用問題です。
このツールは次の前提で作ってあります。

---

## 1. 動かす場所は事務所のPCだけ

**クラウドやレンタルサーバーでは動かさないでください。**
関与先の税務情報と e-Tax の認証情報を、事務所の外に出さないためです。
いつも e-Tax を開いている PC の中で完結させます。

## 2. 暗証番号の持ち方

| | |
|---|---|
| 保存先 | `data\credentials.enc`（1ファイルのみ） |
| 方式 | マスターパスワードから鍵を作って暗号化（scrypt + AES） |
| 平文で出す機能 | **ありません**（意図的に作っていません） |
| 画面表示 | 入力時も伏せ字。ログにも残りません |

- マスターパスワードは紙に書いて金庫へ。**これだけは復旧手段がありません。**
- 環境変数 `ETAX_AUTO_MASTER` に入れておけば毎回の入力を省けますが、
  **共用PCでは絶対にやらないでください。**

## 3. コミット・共有してはいけないもの

`.gitignore` で除外済みですが、念のため：

- `data\clients.csv`（関与先名と利用者識別番号）
- `data\credentials.enc`（暗号化済みでも外に出さない）
- `out\`（関与先の税額そのもの）
- `logs\`（画面のスクリーンショットに法人名が写り込みます）
- `templates\*.pdf`（事務所の様式）

**関与先の情報を含むファイルを、Claude や外部サービスに貼り付けないでください。**
画面の不具合を相談するときは、法人名と税額を塗りつぶしてからにしてください。

## 4. e-Tax への当たり方

- 1社ずつ順番に。同時並行では動かしません
- 社と社の間に必ず間隔を空けます（`settings.toml` の `interval_sec`、既定5秒）
  **0にしないでください。**
- ログイン失敗を繰り返さないよう、リトライ回数を絞っています（既定2回）
- 暗証番号を総当たりするような動きは一切しません

## 5. 出力の保存期間

`out\` には関与先の税額が入った PDF が溜まります。
事務所の文書管理規程に合わせて、定期的に所定の場所へ移すか削除してください。

## 6. 自動操作についての整理

e-Tax の画面をプログラムで操作することは、RPA を使っている事務所と技術的には同じです。
一方で、国税庁が公式に用意している開発者向けの入口は
「国税電子申告・納税システムAPI」であり、こちらはソフト開発業者向けの利用規約に基づきます。

このツールは、人が手でやる操作と同じことを同じ速さでなぞるだけの作りですが、
**公式に認められた手段ではない**点はご承知おきください。
事務所として一度ご判断いただき、必要なら顧問先への説明もご検討ください。

## 7. 最後は人が見る

このツールは印刷物を作るところまでです。
**中身が正しいかの確認と、申告の判断は税理士の仕事**として残ります。
`_結果一覧.csv` の「要確認」は必ず目を通してください。
