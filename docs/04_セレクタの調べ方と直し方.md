# 04 e-Tax の画面が変わったときの直し方

RPA だと画面が変わるたびに録画を取り直しますが、このツールは
**`config/selectors.yaml` というテキストを1行直すだけ**で済みます。
プログラムには触りません。

---

## 考え方

`selectors.yaml` には「どの文字を探してクリックするか」だけが書いてあります。

```yaml
message_box:
  - {text: "送信結果・お知らせ"}
  - {text: "メッセージボックス"}
```

上から順に試し、最初に見つかったものを使います。
だから **候補を増やしておけば、片方の言い方が変わっても動き続けます。**

---

## 直す手順

### 1. 止まった画面を見る

実行中に止まると、その瞬間の画面が `logs\capture\` に保存されます。

```
logs\capture\103245_miss_message_box.png    ← 画面の写真
logs\capture\103245_miss_message_box.html   ← 画面の中身
```

ファイル名の `miss_` のあとが、見つからなかったステップ名です。
上の例なら `message_box` を直せばよいと分かります。

### 2. 実際の文字を確かめる

画像を開いて、押すべきボタンに**実際に書いてある文字**を読みます。
たとえば「送信結果・お知らせ」が「メッセージボックス一覧」に変わっていたとします。

### 3. 候補を足す

`config\selectors.yaml` の該当箇所に、**一番上へ**足します。

```yaml
message_box:
  - {text: "メッセージボックス一覧"}   # ← 足した
  - {text: "送信結果・お知らせ"}
  - {text: "メッセージボックス"}
```

古い候補は消さずに残してください。所轄や画面によって出方が違うことがあります。

### 4. もう一度流す

```
etax-auto run --only 0001
```

---

## 書き方は3種類

| 書き方 | 意味 | 使いどころ |
|---|---|---|
| `{text: "ログイン"}` | その文字を含むリンク・ボタン | **ふつうはこれ**。一番丈夫です |
| `{label: "利用者識別番号"}` | その見出しが付いた入力欄 | 入力欄を指すとき |
| `{css: "#userId"}` | CSSセレクタで直接指す | 上の2つで無理なときだけ |

`css` は画面の作りが少し変わっただけで壊れます。最後の手段にしてください。

---

## 自分で画面を集めたいとき

```
etax-auto capture
```

ブラウザが開くので、**ご自身で手動で** e-Tax を操作します。
記録したい画面まで進んだら、コマンド画面で Enter。
スクリーンショットと HTML が `logs\capture\` に溜まります。終わるときは `q` + Enter。

---

## Claude Code に任せる

この作業こそ Claude Code の出番です。

1. `etax-auto capture` で今の画面を集める
2. Claude Code を起動して、こう頼む

> `logs/capture/` に今のe-Taxの画面を保存しました。
> `config/selectors.yaml` を実際の画面に合わせて直してください。

Claude Code が HTML を読んで、ボタンの文字や入力欄を拾い、
`selectors.yaml` を書き換えます。人がHTMLを読む必要はありません。

---

## 壊れにくくするコツ

- **文字で探す**（`text` / `label`）。画像でも座標でもなく文字。
- **候補を3つくらい持たせる**。言い回しの揺れを吸収します。
- **手動アシストを有効にしておく**（`settings.toml` の `manual_assist = true`）。
  見つからなくても止まらず、人が1回クリックすれば先へ進みます。
  「動かなくなって今日の仕事が止まる」ことがなくなります。
