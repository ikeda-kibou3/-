# 07 残りの作業（チェックリスト）

達人の電子申告アプリに**利用者識別番号と暗証番号の両方**が登録済みであることが
確認できました。ここからの段取りです。

---

## その前に：方式を決めます

**はじめにはっきりさせます。2つの方式は「ダウンロードを自動化するかどうか」が違います。**

| | 方式A | 方式B |
|---|---|---|
| **e-Taxからのダウンロード** | **職員が達人で1社ずつ手作業** | **自動** |
| 対象関与先の抽出 | 自動 | 自動 |
| 1ページ目だけにする | 自動 | 自動 |
| 税額のハイライト | 自動 | 自動 |
| チェックリスト作成 | 自動 | 自動 |
| ①②③(a)(b) の束ね | 自動 | 自動 |
| 成否の記録 | 自動 | 自動 |

もともとのご要望は「決算期が訪れた会社ごとの通知書取得を自動化する」ことでした。
**それを満たすのは方式Bだけ**です。方式Aは、ダウンロードを人がやったうえで
**その後ろを全部自動にする**もので、目的の半分です。

### 方式B（全自動）

```
etax-auto run   → ログインからダウンロード、束ねまで全自動
```

| 良い点 | 引き換えに必要なもの |
|---|---|
| **当初の目的をそのまま満たす** | 暗証番号を当ツールにも登録（70〜80社・一度きりで1〜2時間） |
| 月6〜7社を無人で処理 | **実機での立ち上げ作業**（下の「作業8」） |
| | e-Taxの画面が変わると止まる（手動アシストで続行は可） |

### 方式A（ダウンロードは手作業）

```
達人で個別ダウンロード（月6〜7社）→ 1つのフォルダに集める
        ↓
etax-auto run --from-dir "C:\達人出力\2026-04"
```

| 良い点 | 弱い点 |
|---|---|
| 暗証番号を達人1か所で管理できる | **ダウンロードは自動化されない** |
| e-Taxの画面変更で壊れない | |
| 準備が軽い（ブラウザ部品が不要） | |
| 達人が一括DLを実装したら、そのまま移行できる | |

### 結論：方式Bを目標に、方式Aを保険として持つ

**両方入れてください。** `初回セットアップ.bat` の途中で
「方式Bも使いますか？」に `y` と答えるだけです。

- **本命は方式B。** ただし本物のe-Tax画面で動かすまで、動くとは言い切れません（下記）
- **方式Aは保険。** 方式Bが止まった月でも、達人で落として後工程は回せます
- どちらも**同じ後工程**を使うので、作業1〜7はどちらにも共通です

---

## 正直に申し上げる：検証できていること・できていないこと

| | 状態 |
|---|---|
| 決算期の判定（延長特例・免税・年またぎ） | **検証済み**（テスト82件） |
| PDFのページ抽出・税額ハイライト・チェックリスト差し込み・束ね | **検証済み** |
| 達人の顧問先マスタCSVの取り込み | 模擬CSVで検証。**実物は未確認** |
| PDFフォルダからの取り込み（方式A） | 模擬PDFで検証。**達人の実出力は未確認** |
| e-Taxのログイン〜ダウンロード（方式B） | **自作の模擬サイトでのみ検証。本物のe-Tax画面では一度も動かしていません** |
| Windowsのバッチファイル | **未検証**（開発環境がLinuxのため） |
| チェックリストの印字位置 | **未検証**（原本の実物を見ていないため） |

**方式Bの画面の探し方（`config/selectors.yaml`）は、いただいた手順書の
スクリーンショットから起こした推定です。** 文言が実物と違えば、その箇所で止まります。
止まっても壊れるわけではなく、手動アシストに切り替わって人が1回クリックすれば
先へ進み、その画面が調査用に保存されます。そこを直せば次から自動で通ります。

**つまり「作れるか」ではなく「実機で合わせ込む作業が残っている」という状態です。**
その作業が下の「作業8」で、e-Taxが開けるようになってからでないとできません。

---

## 作業1 達人から顧問先マスタをCSVで書き出す（職員・30分）

達人の顧問先マスタをCSVでエクスポートします。列は多くて構いません。
必要なのは次の5つで、あれば拾います。

法人名 / 顧問先コード / 利用者識別番号 / 決算月（または事業年度終了日）/ 担当者

**暗証番号は書き出さないでください。** 当ツールは使いませんし、
平文のCSVに並べた時点でそれが事務所で一番危険なファイルになります。

## 作業2 関与先マスタに変換する（5分）

```
etax-auto import-clients "C:\達人出力\顧問先マスタ.csv"
```

Shift_JIS のままで読めます。列名は自動で突き合わせ、**対応表を画面に出します。**
当たらなかった列があれば `config/import_map.yaml` に1行足して、もう一度実行してください。

2回目以降の取り込みでも、**手で入れた延長フラグ・有効フラグ・備考は引き継がれます。**
関与先が増えたら、このコマンドを流し直すだけで済みます。

## 作業3 人でしか判断できない4項目を埋める（1〜2時間）

`data/clients.csv` を Excel で開いて確認します。達人から取れない項目です。

| 列 | 入れ方 | 重要度 |
|---|---|---|
| **法人税延長** | 申告期限の延長特例あり → `1` | **最重要** |
| **消費税延長** | 同上（消費税） | **最重要** |
| 消費税課税 | 免税事業者 → `0` | 中 |
| 有効 | 休眠・解約 → `0` | 中 |

**延長フラグを間違えると、その関与先が処理される月がまるごとずれます。**
70〜80社で一番気を使うのはここです。逆にここさえ正しければ、あとは機械が拾います。

保存は必ず「**CSV UTF-8（カンマ区切り）**」で。

## 作業4 検査する（5分）

```
etax-auto check
```

利用者識別番号が16桁か、コードや識別番号が重複していないかを全件調べます。
達人からの取り込みなら誤りは出にくいはずですが、念のため。

続けて、抽出が合っているかを月ごとに見ます。

```
etax-auto plan --date 2026-04-15
etax-auto plan --date 2026-05-15
```

**1年分（12か月）を一通り確認してください。** 全社がどこか1つの月に現れるはずです。
どこにも出てこない関与先があれば、決算月か有効フラグが誤っています。

## 作業5 チェックリストの原本を用意する（1時間）

1. 紙の原本3枚をスキャン（**白黒 / 300dpi / 傾き補正あり**）して `templates/` へ
   - `01_法人税消費税チェックリスト.pdf`（A4縦）
   - `02_法人税チェックリスト.pdf`（A4横）
   - `03_消費税チェックリスト.pdf`（A4横）
2. 印字位置を決める

```
etax-auto calibrate templates\01_法人税消費税チェックリスト.pdf
```

方眼入りのPDFができるので、目盛りを読んで `config\checklists.yaml` の `x` `y` を直します。

3. 位置を確かめる

```
etax-auto run --dry-run
```

`out\` にできたPDFを開いて、法人名・決算期間・担当者の位置を見ます。
ずれていたら数字を直してもう一度。**紙も e-Tax も使わずに何度でもやり直せます。**

## 作業6 事務所PCへ導入する（30分・e-Tax不要）

`docs/08_事務所PCへの導入.md` のとおり、GitHub から ZIP を落として
`C:\etax-auto\` に展開し、`初回セットアップ.bat` をダブルクリックします。
途中の「方式Bも使いますか？」には **`y`** と答えてください（両方入れておきます）。

## 作業7 方式Aを1社で試す（10分・e-Tax必要）

**1社だけ**達人で個別ダウンロードして、保存先のフォルダとファイル名を確認します。

```
etax-auto run --only 0001 --from-dir "C:\達人出力\2026-04"
```

`_結果一覧.csv` の「法人税通知」「消費税通知」が **「取得」** になれば成功です。
**「該当なし」** なら、ファイル名と本文から関与先を特定できていません。
その1社分のファイル名と先頭数行（**法人名と税額は伏せて構いません**）を
お知らせいただければ、突き合わせの条件を合わせます。

## 作業8 方式Bを実機で立ち上げる（1〜3時間・e-Tax必要）★ここが山場

**ここが唯一、実物のe-Tax画面を見ないと終わらない作業です。**
逆に言えば、ここを越えれば毎月はバッチのダブルクリックだけになります。

### 8-1 暗証番号を登録する（1〜2時間・一度きり）

```
etax-auto cred set 1234567890123456
```

最初の1回でマスターパスワードを決めます。**これを忘れると全部登録し直し**なので、
紙に書いて金庫へ。以後は関与先の数だけ繰り返します。終わったら：

```
etax-auto cred verify
```

「有効な関与先すべての暗証番号が登録されています。」と出れば完了です。

### 8-2 1社だけ、画面を見ながら流す

```
etax-auto run --only 0001
```

ブラウザが開いて自動で進みます。**途中で止まったら、それは想定内です。**

```
【手動アシスト】'message_box' を自動で見つけられませんでした。
  ブラウザ画面で「送信結果・お知らせ」を押してください。
  操作が終わったら、この画面で Enter を押してください。
```

この場合は**ブラウザ側でご自身が1回クリックして**、コマンド画面で Enter。
処理はそこから続きます。まずはこの形で最後まで通してください。
1社分の `_束ね.pdf` ができれば、後工程に問題はありません。

### 8-3 止まった箇所を直す

止まった画面は `logs\capture\` に **スクリーンショットとHTML** で残ります。
ファイル名の `miss_<ステップ名>` が、直すべき `config\selectors.yaml` のキーです。

実際のボタンに書いてある文言を、該当キーの**一番上**に足します。古い候補は消しません。

```yaml
message_box:
  - {text: "メッセージボックス一覧"}   # ← 実物に合わせて足す
  - {text: "送信結果・お知らせ"}
  - {text: "メッセージボックス"}
```

### 8-4 止まらなくなるまで繰り返す

```
etax-auto run --only 0001
```

**手動アシストが1回も出ずに通れば完成**です。
経験的に1〜2往復で収まりますが、画面の作りによってはもう少しかかります。

### 8-5 数社で確かめてから全社へ

```
etax-auto run --only 0001 0002 0003
etax-auto run
```

### 行き詰まったら

`logs\capture\` のHTMLを見せていただければ、`selectors.yaml` を実物に合わせます。
**法人名・利用者識別番号・税額は伏せてください。**
ボタンの文言と入力欄の構造だけで直せます。

## 作業9 本番（毎月15日頃）

**方式B（立ち上げが済んでいれば）**

```
etax-auto plan      ← 対象を目で確認（ここは必ず人が見る）
etax-auto run       ← ログインから束ねまで自動
_束ね.pdf を片面印刷
```

`毎月の実行_方式B.bat` をダブルクリックするだけです。

**方式A（方式Bが止まった月・立ち上げ前）**

```
達人で当月分をダウンロード → フォルダに集める
etax-auto plan
etax-auto run --from-dir <フォルダ>
_束ね.pdf を片面印刷
```

PDFのフォルダを `毎月の実行_方式A.bat` にドラッグ＆ドロップします。

## 全体の所要目安

| 作業 | 時間 | 誰が | e-Tax |
|---|---|---|---|
| 1 達人からCSV書き出し | 30分 | 職員 | 不要 |
| 2 変換（import-clients） | 5分 | 誰でも | 不要 |
| 3 **延長フラグ等の記入** | 1〜2時間 | **判断できる人** | 不要 |
| 4 検査と12か月分の確認 | 30分 | 職員 | 不要 |
| 5 チェックリスト原本と位置合わせ | 1時間 | 職員 | 不要 |
| 6 事務所PCへの導入 | 30分 | 職員 | 不要 |
| 7 方式Aを1社で確認 | 10分 | 職員 | **要** |
| 8 **方式Bの実機立ち上げ** | **1〜3時間** | 職員＋池田 | **要** |

作業1〜6（**合計半日弱**）は e-Tax が開かなくても進みます。
**作業8だけが、実物のe-Tax画面を見ながらの作業**です。
