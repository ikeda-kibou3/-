# 毎月のe-Tax決算通知書ルーチン

## 1. まず対象を確認する（必ず先にこれ）

```
etax-auto plan
```

一覧をユーザーに見せて、**実行前に確認を取る**。
勝手に `run` しない。e-Taxへのログインは外向きの操作なので、必ず一声かける。

対象がおかしいときは `data/clients.csv` の決算月・延長・有効フラグを疑う。
プログラムではなくマスタの入力ミスであることがほとんど。

## 2. 実行する

```
etax-auto run
```

- 特定の関与先だけ: `etax-auto run --only 0002 0005`
- e-Taxにつながず試す: `etax-auto run --dry-run`

実行には数分〜十数分かかる。途中で「手動アシスト」の待ちに入ることがあるので、
バックグラウンドに回さず、ユーザーが画面を見られる状態で動かす。

## 3. 結果を報告する

`out/<年-月>申告分/_結果一覧.csv` を読んで、

- 何社が完了したか
- 「要確認」の関与先と、その理由
- 次に人がすべきこと（`_束ね.pdf` の印刷など）

を日本語で簡潔に伝える。**税額などの中身は要約しない**（外部に出さないため）。

## 4. 失敗の切り分け

| メモの内容 | 原因 | 対応 |
|---|---|---|
| 該当なし | お知らせ未着 | 日を置いて `--only` でやり直す |
| ログインに失敗 | 暗証番号の変更 | `etax-auto cred set <識別番号>` を案内 |
| 原本なし | `templates/` にPDFがない | ファイル名を確認 |
| 見つかりませんでした | e-Tax画面の変更 | 下記5へ |

## 5. e-Taxの画面が変わったとき

1. `logs/capture/` の `miss_<ステップ名>.html` を読む
2. 実際のボタン文字・入力欄を拾う
3. `config/selectors.yaml` の該当キーの**一番上**に候補を足す（古い候補は残す）
4. `etax-auto run --only <1社>` で確認

`src/etax_auto/etax.py` は触らない。

## 6. 関与先を追加・変更するとき

1. `data/clients.csv` に行を足す（列の意味は `docs/01_準備するもの.md`）
2. `etax-auto cred set <利用者識別番号>` を**ユーザー自身に**実行してもらう
   （暗証番号を代わりに入力してはいけない）
3. `etax-auto plan --date <その関与先が対象になる月>` で拾えるか確認

## 注意

- 関与先名・利用者識別番号・税額をWeb検索や外部APIに送らない
- `data/` `out/` `logs/` をコミットしない
