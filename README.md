# etax-auto — 決算通知書の取得とチェックリスト作成の自動化

毎月15日頃に行っている「決算の通知書の印刷＆チェックリストの作成」を自動化します。

国税庁 e-Tax にログインし、決算期が到来した関与先ごとに
「法人税及び地方法人税の確定申告について」「消費税及び地方消費税の確定申告について」を
取得して、チェックリストと一緒に **印刷するだけの PDF 1本** にまとめます。

```
etax-auto plan      今月の対象を確認
etax-auto run       取得してPDFを作る
```

---

## これで何が変わるか

| いままで | これから |
|---|---|
| 紙ファイルで識別No.とパスワードを探す | マスタから自動（紙を開かない） |
| 1社ずつログイン→2枚印刷→ログアウトを繰り返す | `etax-auto run` 1回 |
| 消費税は2枚のうち1ページ目だけ選んで印刷 | 自動 |
| 税額に蛍光ペンでライン | 黄色ハイライト付きで出力 |
| チェックリスト3枚をコピーして手書き | 法人名・決算期間・担当者を印字して自動生成 |
| ①②③(a)(b) の順に並べてクリップ止め | `_束ね.pdf` 1本にまとまった状態で出力 |
| どこまで終わったか分からない | `_結果一覧.csv` に全社の成否が残る |

人の仕事として残るのは **印刷・クリップ止め・中身の確認** です。

---

## なぜ RPA ではなく Claude Code か

| | RPA | このツール（Claude Code） |
|---|---|---|
| 画面が変わったとき | 録画を取り直す | `selectors.yaml` を1行直す。Claude に頼める |
| 対象の判定 | 画面操作で表現しづらい | 延長特例や免税事業者も条件で書ける |
| 失敗したとき | 途中で止まる | 止まった画面を保存し、人が1回クリックすれば続行 |
| 記録 | 残りにくい | 全社の成否がCSVとログに残る |
| 変更の履歴 | 追いにくい | テキストなので差分で追える |
| ライセンス費 | 年額がかかることが多い | 無料の部品だけで動く |

## 決算期の判定

実行月の**翌月**に申告月が来る関与先を対象にします（手順書の「決算申告月の前月」に対応）。

```
4月に実行 → 5月申告分 → 3月決算の関与先
```

申告期限の延長特例は関与先ごとに持てます。法人税だけ延長している場合は、
消費税を4月、法人税を5月に、というように自動で振り分けます。
免税事業者は消費税の通知を取りに行きません。

## フォルダの構成

```
config/
  settings.toml       出力先・待ち時間・対象書類名など
  selectors.yaml      e-Tax画面の探し方（画面が変わったらここ）
  checklists.yaml     チェックリストへの差し込み位置
data/
  clients.sample.csv  関与先マスタのひな形
  clients.csv         ★実際の関与先マスタ（各自作成・コミットしない）
  credentials.enc     ★暗号化した暗証番号（自動生成・コミットしない）
templates/            ★チェックリスト原本のスキャンPDF 3枚
src/etax_auto/        プログラム本体
tests/                テスト（e-Taxを模した画面で全体を検証）
out/                  出力（関与先ごとのPDF）
logs/                 ログと、失敗時の画面キャプチャ
```

## 開発者向け

```
pip install -e ".[dev]" || pip install -e .
pip install pytest
playwright install chromium
PYTHONPATH=src python -m pytest tests -q
```

テストは3層あります。

- `test_clients.py` — 決算期の判定（延長特例・免税・年またぎ）
- `test_pdfwork.py` — ページ抽出・ハイライト・束ね・チェックリスト差し込み
- `test_etax_flow.py` — `tests/mock_etax/` に置いた **e-Tax を模した画面**を相手に、
  ログインからPDF保存までの流れ全体を検証（本物のe-Taxにはつながりません）
